# Forumer v0.2.6 release notes

**Status:** release. Date: 2026-11-22.

## What changes in v0.2.6

- **Images in Basecamp:** pictures draw in a Basecamp build that includes the sandbox image provider ([logos-basecamp #514](https://github.com/logos-co/logos-basecamp/pull/514)). A failed full-size fetch keeps the preview on screen and can be retried.
- **Copy text:** the body of a topic or reply can be selected with the mouse and copied.
- **Links:** `http` and `https` links in a post open in the browser when clicked. Other schemes are never opened.
- **Network hint:** when Forumer runs on `logos.test`, the sidebar says that sending needs an RLN membership and points to Settings. Before this, posts stayed on "sending" and then failed with no explanation.
- **Docs:** the README, architecture guide and testing notes describe the current image behaviour and the Basecamp requirement.

## What was checked

| Check | Result |

| Two Basecamp instances on one Mac (macOS arm64), a pre-release build that includes #514, separate Storage homes | The preview arrived with the post and the full image was fetched through Logos Storage and shown, in the public forum. |

| Forumer 0.2.6 installed and ran in Basecamp 0.3.1 | Yes. |

## Known limits

- **Basecamp version.** Images need a build that includes #514 (merged to Basecamp master and on `release/0.4.0`). On older builds a notice replaces the picture and the post text is unaffected.
- **Installer integrity check.** Basecamp builds that include the installed-package check (#533, in recent pre-release builds and on `release/0.4.0`) reject a Forumer package made by the standard build pipeline with an integrity error. The cause is the package layout: LIDL contract files under the root `assets/` folder, plus an icon inside the variant folder. Builds without the check, such as 0.3.1, install it normally.
- **Windows x86_64 is experimental.** The package is cross-built, but it has not been installed or run in a Windows Basecamp. There is no file picker on Windows yet, so attach images by dragging them onto the composer.
- **Networks.** `logos.dev` and `logos.test` are separate. `logos.test` needs an RLN membership to send.
- **Image transfer between two different home networks is untested.** All image tests ran on one machine.
- **Testing two instances on one machine.** Logos Storage keeps one config per computer (`$HOME/.logos_storage`), not one per Basecamp data folder, so each instance needs its own `HOME`.
