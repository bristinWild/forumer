# Forumer v0.2.5 — release candidate notes

**Status:** Candidate, not an authorization to publish. Implementation branch: [`hardening/v0.2.5`](https://github.com/bristinWild/forumer/tree/hardening/v0.2.5). Documentation reviewed 2026-10-18.

## What changes in v0.2.5

- **Security hardening (Phase A):** digest held-set scan budget before expensive work (A1); empty RangeGate admission without charging a cooldown unless an answer is sent (A2); MediaAsk bucket before preview lookup, queued previews and Storage `exists()` (A3).
- **Log privacy (A5):** `scrubIds()`-based shortening of long alphanumeric identifiers; regression coverage for sensitive log patterns; removal of three diagnostic exposures (storage path, peer addresses, request ID and unrestricted transport detail), merged into candidate in commit `3e07c97`.
- **UI:** status indicator and privacy UX notes, including clipboard-manager persistence warning.
- **Images:** PNG/JPEG normalization, previews, re-encoding/metadata stripping and pixel-count guard, tested in CI.
- **Integration:** headless UI checks and manual live-network E3 tests for signed public topic/reply/restart catch-up and private-forum member sync/non-member isolation.
- **Builds:** Linux and macOS regular CI successful; experimental Windows x86_64 cross-build DLL **and** LGX package successful in manually dispatched Actions run #1.

## Unverified, deferred, and known limitations

- **Official Logos Testnet 0.4 E2E not verified.** Check the LP-0026 requirements and access, run the release candidate there, and record exact results before claiming prize acceptance.
- **Windows runtime not verified.** Cross-compilation and package assembly are not proof of install/startup/render/sync in Windows Basecamp. The tag-triggered `release.yml` matrix packages **Linux x86_64, macOS arm64, and Windows x86_64**. Windows packaging has passed, but native Windows Basecamp installation and runtime remain unverified.
- **A3 full backend flood test not executed.** Budget and ordering verified; actual delayed preview callbacks under a flood not stress-tested.
- **A5 complete end-to-end host-log inspection not verified.** Log scrubbing is shape-based, not a general secret detector; dotted IPs, short fragments and mnemonic words are not necessarily caught.
- **WebP decode not verified in CI.** PNG/JPEG covered.
- **No transport-level rate limiting controlled by Forumer.** Per-node admission budgets complement proof-of-work; they are not a global per-sender limit.
- **`storage_module.exists()` cost is not benchmarked.** Budget bounds calls, not worst-case individual latency.
- **Sender transport-failure/outbox restart injection deferred.** Receiver restart/catch-up tested separately.
- **C1–C3 backend split and B5 `/forumer/4` topic cleanup deferred.** Do not delete unknown external topic usage without evidence.
- **Published posts cannot be withdrawn from other peers.** Private invites cannot be revoked; use a newly keyed forum after a leak.
