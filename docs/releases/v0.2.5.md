# Forumer v0.2.5 — Release Candidate

## Runtime compatibility

- Logos Delivery Module v0.4.0
- Logos Storage Module v3.0.2
- Basecamp with the scoped sandbox image-provider fix

The Nix build retains Delivery v0.3.0 as its build-time interface
source. The tested runtime uses Delivery v0.4.0.

## Improvements

- Added MediaAsk rate-limit ordering regression guard.
- Added logging safety checks to CI.
- Added PNG/JPEG image-pipeline tests.
- Verified image resizing, preview generation, metadata stripping
  and the pixel-count guard.
- Added an explicit clipboard-manager privacy warning.

## Verified locally

- Core tests passed.
- Phase A regression guards passed.
- Image-pipeline tests passed.
- Cross-profile topic and image synchronization passed.
- Image rendering and restart persistence passed.
- Modified Basecamp sandbox tests: 14/14 passed.

## Outstanding verification and limitations

- Official Logos Testnet 0.4 end-to-end run is not verified.
- Automated multi-node network tests in CI remain outstanding.
- Full runtime MediaAsk flood and complete posting-cycle log audits
  are not replaced by the new source and fixture checks.
- WebP decoding is not verified in CI.
- Transport-level rate limiting is not implemented by Forumer.
- The runtime cost of storage_module.exists() is not measured.
- Windows builds are not verified.
- Backend separation and unresolved topic cleanup are deferred.

## Release dependency

Image rendering requires the Basecamp sandbox image-provider change:
https://github.com/logos-co/logos-basecamp/pull/514

Forumer compatibility PR:
https://github.com/bristinWild/forumer/pull/3

Do not publish this release generally until the required Basecamp
compatibility is available and candidate CI checks pass.
